# Phase 6 - PDF Extraction Engine

Status: **Complete**. Date: Phase 6 implementation session.

## 1. Phase Overview

Phase 6 introduces NoteMint's **PDF Extraction Engine**, transforming uploaded binary PDF documents into clean, searchable, page-level structured text and diagnostics. The extraction engine extracts metadata, preserves reading layout, normalizes excessive whitespace without destroying paragraph structure, evaluates extraction quality, detects image-only/scanned documents, persists page-level records in PostgreSQL, and exposes extraction status through authenticated APIs and real-time dashboard UI feedback.

Background job processing is powered by **Celery** with **Redis**, designed for asynchronous processing, automatic retry with exponential backoff on temporary storage outages, transactional idempotency, safe temporary file cleanup, and non-blocking upload fallback when background brokers are offline.

## 3. Extraction Engine Architecture

```text
Student Browser / Client
   │
   ├─ POST /api/v1/documents (PDF upload)
   ▼
FastAPI Backend
   │
   ├─ 1. Validate PDF signature & size -> Stream to Neon Object Storage
   ├─ 2. Commit Document record (status='uploaded')
   ├─ 3. Enqueue extraction task to Celery / Redis
   │      └─ Non-blocking: returns 201 Created immediately
   ▼
Celery Worker Process (Redis broker)
   │
   ├─ 1. Load document from PostgreSQL
   ├─ 2. Mark Document & Extraction as EXTRACTING
   ├─ 3. Download original PDF from Object Storage to secure temp file
   ├─ 4. PdfExtractionService (PyMuPDF)
   │      ├─ Extract document metadata (title, author, creation date)
   │      ├─ Extract page text preserving order and paragraph breaks
   │      ├─ Normalize whitespace (collapse excess spacing, sanitize linebreaks)
   │      ├─ Calculate character counts and flag empty / low-text pages
   │      └─ Analyze quality: detect scanned image-only PDFs vs selectable text
   │
   ├─ 5. ExtractionRepository.save_extraction_results()
   │      ├─ Idempotent transaction: replaces old pages if retried
   │      ├─ Bulk insert DocumentPage records
   │      ├─ Update Document.page_count and Document.status
   │      └─ Mark COMPLETED if usable text, or FAILED if scanned/corrupted
   │
   └─ 6. Clean up temporary files in finally block
```

## 4. Why PyMuPDF Was Selected

PyMuPDF (`import pymupdf`, v2.1) was selected as the core engine for NoteMint based on:

1. **Extraction Reliability**: High-fidelity text extraction with native support for reading layout, font metrics, and Unicode character sets.
2. **Page-by-Page Granularity**: Direct access to individual pages (`doc[page_idx]`), enabling discrete page record creation with exact 1-based page indexing.
3. **Embedded Image Inspection**: `page.get_images(full=True)` allows inspecting visual objects on each page to accurately detect scanned/image-only PDFs without external OCR dependencies.
4. **Metadata Extraction**: Clean extraction of internal PDF info dictionaries (Title, Author, Subject, Creator, Producer, CreationDate).
5. **High Performance**: Native C++ core (MuPDF) provides sub-second parsing for multi-page educational materials with low memory overhead.
6. **Robust Error Handling**: Clear typed exception hierarchy (`pymupdf.FileDataError`, `doc.is_encrypted`) allowing distinct handling for corrupted and password-protected files.

## 5. Database Schema & Models

### `DocumentExtraction` (`document_extractions` table)

Stores high-level extraction metrics, metadata, and quality analysis for each document (1:1 relationship with `Document`):

```sql
CREATE TABLE document_extractions (
    id UUID PRIMARY KEY,
    document_id UUID NOT NULL REFERENCES documents(id) ON DELETE CASCADE UNIQUE,
    doc_metadata JSON,
    total_characters INTEGER NOT NULL DEFAULT 0,
    status VARCHAR(32) NOT NULL DEFAULT 'pending',
    engine VARCHAR(64) NOT NULL DEFAULT 'pymupdf',
    quality JSON,
    error_message VARCHAR(1024),
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT now(),
    updated_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT now()
);

CREATE UNIQUE INDEX ix_document_extractions_document_id ON document_extractions(document_id);
```

### `DocumentPage` (`document_pages` table)

Stores structured extracted text for each individual page of the document:

```sql
CREATE TABLE document_pages (
    id UUID PRIMARY KEY,
    document_id UUID NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    page_number INTEGER NOT NULL,
    text TEXT NOT NULL DEFAULT '',
    character_count INTEGER NOT NULL DEFAULT 0,
    has_text BOOLEAN NOT NULL DEFAULT FALSE,
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT now(),
    CONSTRAINT uq_document_pages_document_id_page_number UNIQUE (document_id, page_number)
);

CREATE INDEX ix_document_pages_document_id ON document_pages(document_id);
CREATE INDEX ix_document_pages_document_id_page_number ON document_pages(document_id, page_number);
```

### Document Status Lifecycle

The document status lifecycle progresses cleanly through:

```text
   uploaded
      │
      ▼
  extracting
      │
      ├───────────────────────┐
      ▼                       ▼
  completed                failed
(usable text)        (scanned / corrupted / limit)
```

- If a PDF is image-only / scanned with no usable selectable text, `Document.status` is set to `failed` and `DocumentExtraction` records `quality.is_scanned = True`, `quality.ocr_required = True`, and `error_message = "Scanned or image-only PDF. OCR is required to extract text."`.
- NoteMint never falsely marks a scanned PDF with 0 usable text as completed.

## 6. Celery & Redis Background Worker

### Configuration (`backend/app/core/celery_app.py`)

- Broker URL: `redis://localhost:6379/0` (configurable via `REDIS_URL` or `CELERY_BROKER_URL`).
- Result Backend: `redis://localhost:6379/0` (configurable via `CELERY_RESULT_BACKEND`).
- `task_acks_late = True`: Task acknowledged only after successful completion, preventing lost tasks on worker crashes.
- `worker_prefetch_multiplier = 1`: Fair dispatch among workers.
- `broker_connection_timeout = 1.0` and fast socket probing: Prevents upload HTTP handlers from hanging if Redis is offline.
- Automatic retry on storage failure: `StorageUnavailableError` triggers retry with exponential backoff (10s, 20s, 40s) up to 3 attempts.

### Windows Compatibility Note

On Windows, the default Celery multiprocessing pool can encounter pipe permission errors. Workers should be started with the solo execution pool (`-P solo`):

```powershell
celery -A app.core.celery_app worker --loglevel=info -P solo
```

## 11. Security and Reliability Considerations

1. **Owner Isolation**: User ownership is strictly verified against Clerk JWKS JWT `sub` claims before extraction results are returned. A student cannot view extraction data for documents owned by other students.
2. **Resource Exhaustion Protection**: Configurable `MAX_EXTRACTION_PAGES = 500` and `MAX_EXTRACTION_TEXT_LENGTH = 10,000,000` protect against decompression bombs or excessive memory consumption.
3. **Password Protection Handling**: Password-protected PDFs are rejected gracefully with typed `EncryptedPdfError` without hanging or exposing internal stack traces.
4. **Temporary File Safety**: Files streamed from private object storage to disk use `tempfile.NamedTemporaryFile` with guaranteed deletion in `finally` blocks, preventing disk exhaustion.
5. **No Secret or Text Logging**: Structured logs record document UUIDs, page counts, and character lengths; raw extracted document contents and storage keys are never logged.
6. **Non-Blocking Fallback**: Fast socket pre-checks prevent upload endpoints from hanging if the Celery Redis broker is temporarily unreachable.

## 12. Current Limitations & What Phase 7 Needs to Know

- **No OCR in Phase 6**: Image-only and scanned PDFs are detected and marked as requiring OCR, but OCR is not performed. A future phase can add an OCR pipeline (e.g. Tesseract or vision model).
- **Extracted Text Ready for Phase 7**: Extracted text is stored in `document_pages` with `page_number`, `text`, `character_count`, and `has_text`.
- **Phase 7 AI Generation Engine** can query pages directly via `ExtractionRepository.get_pages_for_document(doc_id)` to construct prompts for:
  - Smart summary notes
  - Important CBSE/exam questions with model answers
  - Active recall flashcards
  - Diagnostic MCQ quizzes
