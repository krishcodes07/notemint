# Phase 1 - Project Foundation & Setup

Status: **Complete**. Date: Phase 1 implementation session.

## 1. Phase Overview

Phase 1 established the NoteMint foundation: inspected and configured the existing Next.js 16 frontend (design system, typography, shadcn/ui, light/dark theme), initialized a modular FastAPI backend with centralized configuration and a health endpoint, and connected the two through a centralized frontend API client with loading/success/error states.

## 2. Objectives

- Configure the existing Next.js app (TypeScript, Tailwind v4, shadcn/ui, Lucide).
- Establish a green NoteMint design system with light + dark themes and Geist typography.
- Build a minimal, responsive foundation/landing page showing branding and theme consistency.
- Initialize a clean FastAPI backend with Pydantic Settings, CORS, logging, error handling.
- Expose `GET /api/v1/health`.
- Connect frontend to backend via `NEXT_PUBLIC_API_URL` with a status UI.
- Verify everything (build, lint, tests, live checks) and document it.

Out of scope (per instructions): authentication, database, PDF processing, AI features.

## 6. Architecture and Implementation Explanation

### Frontend foundation

- **Kept the existing app** (Next.js 16.4.4, App Router, Tailwind v4 via `@tailwindcss/turbopack`). Read bundled version-matched docs from `node_modules/next/dist/docs/` as required by `frontend/AGENTS.md`.
- **Design tokens**: brand colors live once as `--brand-*` in `:root` / `.dark` in `globals.css`. shadcn semantic vars (`--primary`, `--background`, ...) reference them, so changing a brand color is a one-line edit. Tailwind utilities `bg-brand-primary`, `text-brand-secondary`, `bg-brand-soft` are exposed through `@theme inline`.
- **Theme**: class strategy (`.dark` on `<html>`). An inline `<head>` script applies the class before hydration from `localStorage("theme")` or `prefers-color-scheme` — no flash. `ThemeToggle` uses `useSyncExternalStore` (React-recommended) instead of `useState`+`useEffect` to satisfy the `react-hooks/set-state-in-effect` lint rule; it also subscribes to OS color-scheme changes.
- **Typography**: Geist + Geist Mono already loaded via `next/font/google` (preferred per requirements). Variables `--font-geist-sans`/`--font-geist-mono` are mapped to Tailwind `font-sans`/`font-mono`; `html` gets `font-sans` in `@layer base`.
- **Landing page**: header, hero, feature grid (6 resources), how-it-works steps, live system-status card, AI Teacher teaser, footer. Responsive via Tailwind grid breakpoints (`1 → sm:2 → lg:3`).

### Backend foundation

```text
backend/
├── app/
│   ├── api/v1/        routers (health)
│   ├── core/          config.py, logging.py
│   ├── services/      (empty until business logic exists)
│   └── main.py        app entry, CORS, handlers
├── tests/
├── pyproject.toml
└── .env.example
```

- **Configuration**: `Settings(BaseSettings)` loads `.env` + environment variables (case-insensitive), validates `LOG_LEVEL`, exposes `cors_origins` and `is_development`. Cached via `@lru_cache`; module-level `settings` singleton.
- **CORS**: `CORSMiddleware` with `allow_origins = [frontend_url]` (from env), credentials enabled.
- **Logging**: configured once at import (`configure_logging()`): stdout handler, `LEVEL | name | message` format, uvicorn access quieted in development.
- **Error handling**: `RequestValidationError` → 422 with `{detail, errors}`; catch-all `Exception` → logged 500 with generic `{detail}` (no stack traces leaked).
- **Entry point**: `main.py` creates the app with lifespan logging; routers included under `settings.api_v1_prefix`. Swagger docs enabled only in development.

### Connectivity

- `frontend/lib/api.ts` is the single place that knows the backend URL (`NEXT_PUBLIC_API_URL`, fallback `http://localhost:8000`). It wraps `fetch`, distinguishes network failure (`BackendUnavailableError`) from HTTP errors (`ApiError`), and exposes typed helpers (`getHealth()`).
- `HealthStatus` (client component) demonstrates the three required states: loading spinner, success (`service is status`), error message + Re-check button. Initial load runs in `useEffect` with a cancellation flag; `setState` only occurs in async callbacks (lint-compliant).

## 7. Important Technical Decisions

1. **Next.js 16 bundled docs** were read before coding (breaking changes: Turbopack default, async request APIs, `middleware`→`proxy`, `next lint` removed, `cacheComponents` on). No incompatible APIs were used.
2. **shadcn preset "nova"** chosen because it targets Lucide + Geist — exactly NoteMint's stack. Base library: radix.
3. **`cn` imported from the `cn` package** (`import { cn } from "cn"`), matching what shadcn v4 generates — do not rewrite to `@/lib/utils` unless standardizing later.
4. **Class-based dark theme** (not `prefers-color-scheme` only) so users can override; OS preference is the default when no choice stored.
5. **`useSyncExternalStore` for theme** over `useState`/`useEffect` — avoids hydration mismatch and passes the new React hooks lint rules.
6. **Single health card as the connectivity test** instead of adding a test framework to the frontend (test frameworks arrive in Phase 12).
7. **Backend keeps `services/` empty** — placeholder only, no premature abstraction.
8. **`/api/v1/health/info`** added as a small dev helper (environment info); the required contract is `/api/v1/health`.
9. **Editable install** (`pip install -e ".[dev]"`) so local edits apply without reinstalling.
10. **Root `.gitignore` created** because none existed; frontend `.gitignore` amended with `!.env.example`.

### Issues found and fixed during testing

1. **ESLint `react-hooks/set-state-in-effect`** in `ThemeToggle` → switched to `useSyncExternalStore`.
2. **Same rule in `HealthStatus`** → split into pure `requestHealth()` (returns state) + `setState` only in `.then` callbacks with cancellation flag.
3. **Unused `Upload` import** in `page.tsx` → removed.
4. **`Start-Process npm` failed silently** (npm.cmd on Windows) → used `cmd /c npm run dev`.
5. **pyproject `readme = "README.md"` warning** (file missing in backend/) → removed the field.

## 10. Issues Encountered and Their Solutions

- **Next.js 16 unfamiliar APIs**: resolved by reading `node_modules/next/dist/docs/` (version-matched) before editing — per `AGENTS.md`.
- **shadcn `init` hung on interactive preset prompt** even with `-y` → re-ran with explicit `-p nova -b radix --no-monorepo`.
- **Circular `--font-sans: var(--font-sans)`** in shadcn-generated `@theme inline` → fixed to `var(--font-geist-sans)`.
- **Root `.gitignore` missing** → created; also fixed frontend ignoring `.env.example`.
- **`react-hooks/set-state-in-effect` errors** → see testing section (patterns above).
- **Starlette TestClient deprecation warning** (`httpx` → `httpx2` suggested by FastAPI 0.162): harmless, noted for future upgrade; not acted on.

## 11. Current Limitations

- No authentication, database, storage, PDF processing, or AI (by design — Phase 2+).
- Landing page CTAs ("Get started", "Upload a PDF") are intentionally disabled.
- Dark theme verified via compiled CSS + toggle logic + lint/build; no automated browser screenshot test (no test framework until Phase 12).
- CORS allows a single origin (`FRONTEND_URL`); no wildcard and no multi-origin list yet.
- Backend has no rate limiting, auth middleware, or structured request logging (later phases).
- `services/` layer is empty; no domain modules yet.
- Frontend `.env.local` not created (defaults suffice); production env wiring deferred to Phase 12.
